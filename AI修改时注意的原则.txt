你正在维护一个“严格离线可用”的本地工具项目。必须遵守以下硬约束，任何情况下都不能违反：

【离线与安全硬约束】
1. 禁止引入任何联网能力
- 禁止新增或保留任何外部 URL 依赖（http/https）。
- 禁止使用 CDN、远程脚本、远程样式、远程字体、远程图片、远程 API。
- 禁止新增 fetch / XMLHttpRequest / axios / WebSocket / EventSource / sendBeacon / import('http...') 等。
- 禁止 service worker 做联网缓存策略（若有仅允许纯本地离线资源）。
- 禁止任何“自动更新”“远程配置”“远程埋点”“错误上报”。

2. 仅允许本地依赖
- 所有第三方库必须使用项目内本地文件（如 assets/vendor/*）。
- 若必须新增依赖，先下载到本地并固定版本，再引用本地相对路径。
- 不允许“latest”语义的依赖来源。

3. 必须保持并强化 CSP 离线策略
- 保持每个 html 的 CSP 为离线模式，至少满足：
  - connect-src 'none'
  - default/script/style/img/font/media 仅允许 self + 必要的 data/blob
  - 禁止 object/frame
- 修改后不得放宽 CSP 以换取功能。

4. 功能优先级
- 任何改动都不得破坏现有离线功能（导入/导出/压缩/校验/本地存储/复制等）。
- 如果需求与离线硬约束冲突，必须拒绝联网方案，并给出纯本地替代实现。

5. 输出要求（每次改动后必须自检并汇报）
- 明确列出：本次是否新增任何外部依赖（必须为否）。
- 明确列出：是否存在任何联网 API 调用（必须为否）。
- 明确列出：CSP 是否仍满足离线限制（必须为是）。
- 如果发现风险点，先修复再结束，不得忽略。

【执行策略】
- 优先做“本地实现/本地库替换/静态资源内置”。
- 不要为了省事引入在线服务。
- 不要建议“临时用 CDN”，即使是开发环境也不允许。
