## 总结判断

当前项目不是缺少 Token，而是缺少唯一权威：

- `tokens.css` 已定义 32/28px 控件、4/6/8/12/16/24px 间距和 4/6/8px 圆角。
- 页面层又出现 14px App Shell 圆角、34px 首页按钮、蓝色选中竖条、首页蓝色径向光晕、模块自有 Radix 控件和大量原生控件。
- 图片水印、视频水印和 Logo 工作台虽共享主题颜色，但信息架构、控件名称、状态语义和输出区位置仍明显分叉。

后续不能先“换皮”。先统一功能语义和 UI 度量，再做视觉收口。

## 统一 UI 度量基线

| 项目 | 统一规则 |
|---|---|
| 工作台应用标题 | 16px / 600 |
| 页面/面板标题 | 14px / 650 |
| 分组标题 | 12px / 650 |
| 正文/控件 | 13px / 1.45 |
| 标签/说明/状态 | 12px / 1.4 |
| 数值 | 12px，`tabular-nums` |
| 默认控件 | 32px 高 |
| 紧凑控件/图标按钮 | 28px 高，点击区域不小于 28×28px |
| 首页主标题 | 最多 24px；只在工具箱首页使用 |
| 间距 | 4 / 6 / 8 / 12 / 16 / 24px；移除未说明的 10/14/18/20px 页面常量 |
| 控件圆角 | 4px |
| Panel / Tool Card | 8px |
| Dialog | 8–10px |
| Pill | 仅状态 Badge / Toggle |
| 边框 | 1px；默认低对比，hover/focus/selected 提升，不改变布局 |
| 动效 | 常规 120ms，浮层 180–220ms；尊重 reduced motion |
| 图标 | Lucide 16/18px，stroke 1.5–1.8 |

## 状态统一决策

- 导航和列表 selected：中性略亮背景 + 低对比边框 + 文字提升；不使用左侧彩色竖条、渐变或 glow。
- 键盘 focus：统一 1px focus ring + 1px offset；鼠标点击后不常驻。
- Primary：只用于当前页面唯一主操作；避免同屏多个高饱和蓝按钮争夺注意力。
- Disabled：文字、边框和背景共同降级并保留 `not-allowed`，不能只降透明度。
- Warning / Error / Success：统一语义 Token；不在每个模块自定义颜色和徽章。
- Accent：保留语义变量，最终色值在 UI 第一阶段确认；不把当前高饱和蓝或附件中的淡紫直接写死到业务组件。

## 问题台账

### P0｜必须先于视觉重构解决

1. **水印度量语义分叉**
   “间距”实际是中心步长；视频还同时维护间距和行列数。先执行 `WATERMARK_MEASUREMENT_UNIFICATION_PREP.md`，否则 UI 控件只是包装错误模型。

2. **预览画布承担隐藏操作**
   图片预览整块画布按下会临时隐藏水印，同时页面又有“按住查看原图”按钮。画布应保持被动预览，只保留明确控件，消除“点击预览到底是刷新、对比还是没有反应”的不确定感。

3. **视频底帧刷新与水印重绘未完全解耦**
   参数变化不再跑 FFmpeg，但仍会重新解码同一底帧。需要先建立“底帧只因素材/时间变化，水印每次参数变化即时重绘”的行为契约和像素级测试。

4. **同一控件存在多套实现**
   项目同时使用 `src/components/ui`、原生 button/select/range、模块内 Radix Select/Slider/Tabs 和局部 CSS。后续 UI 迭代前应先决定哪些 Radix 能力被包装进共享 Primitive，不允许继续在业务模块中直接增加第五套样式。

### P1｜UI 第一轮

1. **ModuleNav 选中态违反新方向**
   当前存在蓝色背景、蓝色描边和左侧蓝色竖条。改为中性背景/边框/文字明度，不改变导航结构。

2. **App Shell 圆角和边界脱离 Token**
   顶栏、模块容器和面板大量使用 14px 圆角；Token 与现有 UI 指南是 4/6/8px。第一轮统一到 Panel 8px、控件 4px、Dialog 8–10px。

3. **工具箱首页偏展示页**
   英文 eyebrow、径向蓝光、网格背景、较大品牌图标和大卡片让首页更像 Landing Page。收敛为紧凑工具启动器：标题、分组、工具行/小卡、状态与本地处理说明。

4. **高饱和蓝使用范围过大**
   导航、按钮、滑块、选中素材、图标底和首页装饰同时使用蓝色。Accent 只保留在 focus、唯一主操作、进度和关键 selected 状态。

5. **图片/视频水印信息架构不同**
   图片为素材/预览/参数三栏；视频为素材/预览/设置三栏加整行输出队列。允许任务结构不同，但相同概念必须同名、同控件、同顺序：内容 → 排列 → 大小/角度/透明度 → 输出。

6. **输出操作位置不统一**
   图片导出在预览标题，输出尺寸在 Inspector；视频输出目录和质量在底部队列区。后续统一“预览区只预览，右侧设置参数，底部/标题主操作负责输出”的规则，具体布局在不改流程前提下确认。

7. **说明文案过多且层级相近**
   视频页同时解释实时 Canvas、推荐、时间轴释放、GPU、输出目录和队列冻结。保留影响决策的信息，其余放 tooltip/title 或仅在状态变化时出现。

8. **基础控件状态仍由页面 CSS 覆盖**
   `components.css` 已有全局状态规则，业务 CSS 又覆盖 Radix Trigger、按钮和输入框。第一轮清理重复定义，避免增加新 override 文件。

### P2｜工具页收口与可访问性

1. 图片 Inspector 较长，滚动后缺少稳定的上下文标题；可考虑 sticky 面板标题，但不做多层 sticky。
2. 视频空状态展示大量 disabled 控件和弱对比说明，主任务“先选视频”不够突出。
3. “源 / 输出预览”实际只有一个合成预览，应改为“水印预览”或真正提供对比后再使用该名称。
4. “重新推荐”容易被理解为刷新，应改为“重新适配画面”，并提示会覆盖当前参数。
5. “规则平铺 / 错位平铺 / 密度 / 间距 / 行列”术语需要随水印契约统一。
6. 设置弹窗当前只有一个启动偏好，不应为了参考稿强行增加 Tabs 或空分组；保持小而完整。
7. 需要补 1100×720、1280×720、1440×900、1920×1080 的同状态截图；当前只完成 1440×900。
8. 截图不能证明完整对比度、键盘顺序、屏幕阅读器和原生 WebView 高 DPI，需要后续 DOM 与 Tauri 实机验证。

## 建议删除

- ModuleNav 左侧选中竖条、首页大范围蓝光和网格装饰。
- 画布点击/按下触发原图对比的隐式操作。
- 与可见控件重复的常驻说明。
- 页面级基础控件颜色、高度、圆角常量和第三层 override。
- 水印业务状态中重复的行列真值。

## 建议保留

- 现有桌面三栏工作台、72px 模块导航和中央深色画布区。
- `src/components/ui` 的现有 API 方向，逐步补齐而不是建立第二套系统。
- Lucide 图标、系统字体、本地离线运行和现有 Render Plan / 导出链路。
- 图片与视频不同任务所必需的时间轴、输出队列和素材差异。
- 现有 32/28px 控件与 4/6/8/12/16/24px 间距 Token 作为新基线。
