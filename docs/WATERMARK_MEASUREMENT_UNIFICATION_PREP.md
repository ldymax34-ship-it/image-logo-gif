# 水印度量统一筹备

日期：2026-08-17
状态：分析完成，未实施

## 目标

把图片水印、视频预览和视频正式输出收敛为一套度量、排列和刷新语义，避免继续通过反复调整默认像素值修补视觉结果。

默认视觉目标：相对密集、45°、砖型错位排列；水印之间有稳定留白，不接触、不大面积重叠；修改参数后无需点击预览或手动刷新。

## 已确认的根因

1. 当前 UI 把 `spacingX / spacingY` 称为“横向间距 / 纵向间距”，实际渲染把它们当作水印中心点步长，不是水印边界之间的空隙。
2. 默认文字在 1920×1080、字号 5%、旋转 45° 时，预览中单个水印的旋转后可见包围盒约为 736×736 源像素；中心点步长仍是 220×160，因此必然大量重叠。
3. 当前“错位平铺”只把奇数行横移半个中心步长；水印本身旋转了 45°，但排列网格没有跟随旋转，所以它不是一套真正的 45° 砖型晶格。
4. 图片水印默认仍是 `tiled`（规则平铺），不是用户要求的 `staggered / brick`。
5. 视频配置同时保存 `spacingX / spacingY` 与 `tileColumns / tileRows`。一旦行列数存在，Render Plan 会进入行列分支并忽略间距值；UI 却继续用间距推断“密集 / 适中 / 稀疏”。同一个配置存在两套真相。
6. 视频水印参数已不再触发 FFmpeg 刷新，但 `VideoWatermarkCanvas` 每次参数变化仍会重新创建并解码同一底帧图片，快速连续调整时旧绘制会被取消，仍可能产生“没有当次刷新”的感受。
7. 当前测试主要确认 Canvas 节点没有被替换、FFmpeg 没有重跑，没有确认水印像素或绘制指令在当次参数变化后已经更新。

## 当前度量分叉

| 概念 | 图片水印 | 视频预览 / 输出 | 问题 |
|---|---|---|---|
| 字号 | 画布短边百分比 | 画布短边百分比 | 基本一致，可保留 |
| 间距 | 固定源像素中心步长 | 固定像素、密度预设、行列数并存 | 含义不一致，且不随内容长度变化 |
| 砖型 | 奇数行水平偏移 | 视频暂不支持 | 图片也不是真正的旋转砖型晶格 |
| 密度 | 两个数字输入 | 三档密度 + 推荐行列 | 两套控制映射到不同真值 |
| 推荐 | 无 | 同时写间距与行列 | 推荐结果会遮蔽用户可见间距 |
| 刷新 | React 预览即时重算 | 底帧请求 + Canvas 叠加 | 底帧与水印绘制仍未彻底解耦 |

## 统一后的唯一业务契约

### 1. 用户可见参数

- `pattern`：`single | brick`。默认 `brick`。
- `angleDeg`：角度，默认 45°。
- `sizePercent`：水印高度相对画布短边的百分比，继续沿用当前定义。
- `opacity`：0–100%。
- `density`：`dense | standard | sparse`，是普通用户的主控制。
- `phase`：砖型错位比例，默认 0.5；放在高级设置，不作为日常主控。
- `offsetX / offsetY`：业务层使用画布比例或统一短边单位；UI 可按当前输出尺寸换算显示像素。

### 2. 唯一间距定义

不再把中心步长叫“间距”。统一使用水印自身高度作为节奏单位 `h`：

- `inlineGap`：同一行相邻水印之间，沿文字基线方向的净空，单位为 `h`。
- `rowGap`：相邻砖行之间的净空，单位为 `h`。
- `cellWidth = contentWidth + inlineGap × h`
- `rowStep = contentHeight + rowGap × h`

密度预设只写入这两个值，不再同时写行列数：

| 预设 | inlineGap | rowGap | 视觉目标 |
|---|---:|---:|---|
| 密集（默认） | 0.75h | 1.0h | 留白清楚但连续覆盖 |
| 适中 | 1.5h | 1.75h | 日常通用 |
| 稀疏 | 2.5h | 2.75h | 低干扰覆盖 |

以上数值是第一轮实现起点，必须通过默认长版权文字、短中文和 Logo 三类素材目视校准；语义不再改变。

### 3. 真正的 45° 砖型排列

先在水印自身坐标系建立砖型晶格，再把整个晶格与每个水印一起旋转：

```text
A = Rotate(angle) × (cellWidth, 0)
B = Rotate(angle) × (phase × cellWidth, rowStep)
position(row, column) = origin + column × A + row × B
```

这样 45° 是排列方向，不只是单个文字的旋转角度。行列数仅由画布覆盖范围和上述晶格向量推导，不进入业务状态，不出现在用户设置里。

### 4. 内容测量

- 文字使用已加载的思源黑体和 Canvas `measureText` 得到实际宽度、上升部与下降部。
- 多行文字先形成一个整体内容框，再参与砖型排列；不把每一行误当作独立砖块。
- Logo 使用其最终显示宽高。
- 几何函数只接收已经测量好的 `contentWidth / contentHeight`，避免在核心算法里混入 DOM、Canvas 或 FFmpeg 依赖。

### 5. 图片与视频同源

- 图片预览、图片导出、视频 Canvas 预览和视频 FFmpeg 输出都消费同一个 placement plan。
- 视频正式输出继续接收百分比 placements；`columns / rows / spacingX / spacingY` 不再作为并列真值。
- 推荐能力只能返回统一契约中的 `sizePercent / angleDeg / density`，或直接返回 `inlineGap / rowGap`；不能再额外返回会覆盖它们的行列数。

## 统一刷新语义

### 图片

- 设置改变后下一帧直接更新预览。
- 预览画布本身不承担刷新、切换或隐藏水印的隐式点击行为。
- 原图对比只保留一个明确、可键盘操作的“按住查看原图”控件；画布点击不再执行同一动作。

### 视频

- 选择视频、切换素材或释放时间轴时，才请求新的干净底帧。
- 修改文字、字号、透明度、角度、排列或密度时，只重绘叠加层，不请求 FFmpeg、不重新解码底帧。
- 底帧按 object URL 缓存为已解码图片或 `ImageBitmap`；水印层变化只执行 `clear → draw base → draw layers`。
- “重新推荐”不是刷新，应改为“重新适配画面”，并明确它会修改水印参数。
- 状态文案只区分“正在获取底帧”和“预览已更新”，不出现含糊的“刷新水印”。

## 默认效果验收

以默认文案 `©KURO GAMES ALL RIGHTS RESERVED`、1920×1080、字号 5%、45°、密集砖型为基准：

1. 画面形成约 4–6 条连续对角砖行。
2. 约 10–18 个完整或边缘裁切的水印实例可见，不出现当前 200+ 实例的纹理化堆叠。
3. 相邻文字轮廓肉眼不接触；行间没有大块空洞。
4. 奇偶行稳定错开 50%，整体方向与文字方向一致。
5. 横版、竖版、方图改变的是覆盖数量，不改变“密集”的视觉含义。
6. 修改文案长度、字号或角度后，间距自动基于新内容框重算。

## 实施顺序

1. 新增纯几何 brick placement 函数和内容尺寸输入契约。
2. 删除业务状态中的 `tileColumns / tileRows` 真值；行列只作为推导结果或调试信息。
3. 把现有间距预设迁移为统一 density → gap 映射。
4. 图片预览与导出接入新 plan。
5. 视频 Canvas 与 FFmpeg placements 接入同一 plan。
6. 拆分视频底帧解码与水印层重绘。
7. 最后调整 UI 文案与默认值，不先靠改数字掩盖算法问题。

## 测试门禁

- 几何：砖型向量、50% 相位、不同角度、横竖方画布覆盖、实例上限、确定性。
- 视觉安全：默认文字、短中文、多行文字、Logo 均无轮廓接触或异常空洞。
- 同源：图片预览/导出与视频 placements 的中心坐标误差不超过画布边长的 0.5%。
- 刷新：每次配置变化都产生新绘制调用或像素结果；不能只断言 Canvas DOM 节点相同。
- 性能：连续拖动滑块不启动 FFmpeg，不重复解码同一底帧，实例数保持有界。
- 回归：单个水印、锚点、批量图片导出和视频草稿队列行为保持不变。

## 明确不做

- 不新增自由画布、拖拽水印、图层或关键帧。
- 不引入新的渲染引擎、字体运行时或远程依赖。
- 不在本轮筹备阶段修改功能代码、默认配置或用户界面。
