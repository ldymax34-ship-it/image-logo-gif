# UI / 导出体验复盘与实施规格

日期：2026-08-17

## 目标

把当前「平均灰、连续表单、调试浮窗」的观感，收敛成一套适合桌面生产工具的深色 dashboard 视觉系统；参考用户提供的三张图，以及 Aceternity UI、Animate UI、Origin UI 的布局与交互规律，但不复制源码、不增加 UI 依赖、不引入装饰性循环动画。

## 参考证据

- 用户参考 1：深色侧栏 / 选中项局部紫红光晕；其余区域保持近黑、中性、低对比。
- 用户参考 2：处理中 / 成功 / 失败卡片共享相同结构，颜色只用于状态边缘、图标和弱光晕；关闭动作明确。
- 用户参考 3：dashboard 卡片靠大留白、清晰数字层级、细边框和少量语义色区分信息。
- Aceternity：组件按 Sidebar / Tabs / File Upload / Stateful Button / Animated Modal 分离；上传入口只有一个明确动作，异步按钮把 loading / success 状态合并进原操作。
- Animate UI：Progress、Dialog、Files、Sidebar、Tabs 等建立在无障碍 primitives 上；动画用于状态转场，而不是持续抢注意力。
- Origin UI：File Upload、Notification、Select、Slider、Tabs 等按单一职责提供多个组合；适合借鉴控件密度、卡片间距和状态反馈。

网页截图保存在 `artifacts/ui-reference-audit/2026-08-17/`。

## 当前体验问题

### 1. 全局视觉层级

- 主面板 `#545454` 过亮，工作区、面板、输入框之间都依赖大面积灰块，视觉重量平均。
- 边框普遍偏亮，面板像被框线切碎，而不是自然分层。
- 蓝色主按钮与新参考方向不一致；状态色、选中色、主要动作没有形成统一规则。

### 2. 全局导出中心

- 右下角浮层宽度和信息密度偏小，像调试任务监视器，不像产品级任务中心。
- 四个统计值没有独立容器，任务、统计、底部操作之间的节奏不足。
- 当前自动展开逻辑可能在用户主动收起后因同一批任务数量变化再次打开，打断工作。
- 完成、失败、处理中缺少清晰的图标/色带/弱光晕层级。

### 3. 批量导出对话框

- 右栏把命名、格式、体积、语种、结果连续堆叠，用户需要从上到下解释每一个控件。
- 命名模式、体积策略、语种模式本质是互斥决策，但当前 select / radio / 普通字段混用，层级不一致。
- 预览是核心验证区，但左右栏过重，设置栏的连续灰底降低了预览主导性。

### 4. 视频输出配置与本地队列

- 输出目录、格式、质量、GPU 与任务队列连成一大片，缺少「先配置输出，再执行任务」的两步结构。
- 队列动作全部放在标题右侧，禁用状态较多，第一眼不容易判断下一步。
- 任务行已有真实状态与路径，但完成/失败/处理中仍主要依赖小文字，状态扫读效率不足。

### 5. 通知

- 当前顶部胶囊把整张通知做成可点击按钮，关闭方式不够明确，也不能很好承载错误文本。
- 成功 / 失败 / 处理中应该共用稳定卡片结构，仅状态图标、细色带和弱光晕变化。

## 实施规格

### A. 全局 dashboard 深色 token

仅调整既有 token 与组件 CSS，不增加依赖：

- `--color-canvas-deep: #111113`
- `--color-canvas: #151517`
- `--color-app: #1a1a1d`
- `--color-panel: #202024`
- `--color-panel-muted: #25252a`
- `--color-panel-raised: #2b2b31`
- `--color-field: #1d1d21`
- `--color-field-hover: #27272d`
- `--color-border: #34343b`
- `--color-border-strong: #474750`
- `--color-text: #f4f4f5`
- `--color-text-muted: #b0b0b8`
- `--color-text-faint: #777780`
- 主交互：`#6f72f6`，hover `#8184ff`，soft `rgb(111 114 246 / 16%)`
- 成功：`#49d7a8`；失败：`#ff708f`；警告：`#f2b966`
- 面板默认 10–12px 圆角，细边框；阴影只用于对话框、浮层和通知。
- 允许在导出中心 / 通知顶部使用单个低透明度径向光晕；禁止全页发光、跑马灯、循环 shimmer。

### B. 导出中心

- 展开宽度约 420px，最大高度约 620px，14px 圆角。
- 头部：图标 +「导出中心」+ 当前进行中数量；关闭为独立按钮。
- 统计：四个紧凑 stat cards，使用数字层级；完成/失败仅数字与细边框使用语义色。
- 任务：状态图标、真实输出名、来源与尺寸/体积、百分比、进度条；失败详情保持可读。
- 交互：
  - 新 `batchId` 第一次出现时可自动展开。
  - 用户主动收起后，同一批次的进度与成员变化不得反复自动打开。
  - 新失败可以自动展开；全隐藏时不渲染；清除只影响当前可见终态任务。
- 收起态是稳定的「导出中心」pill，显示进行中或失败计数。

### C. 批量导出

- 保留「文件列表 / 大预览 / 设置」三栏，不改变任务构建与写文件逻辑。
- 右栏改为三个 section cards：
  1. `文件命名`：源文件名 / 自定义名使用 segmented buttons；批次名跟随其下。
  2. `格式与体积`：PNG/JPG segmented；质量、体积策略和自动压缩放在同组。体积策略改为三个可点击 radio cards，不再用 select。
  3. `语种`：三个 compact radio cards；只有「追加其他语种」时展开语种选择。
- 结果摘要单独成卡；帮助文案放到最下方，不和设置混排。
- footer 保持唯一主操作；导出中按钮内显示状态，进度条在 footer 中清晰可见。

### D. 视频输出与队列

- 将底部区域明确拆成两层：
  1. `1 · 输出配置` card：输出目录置顶，格式/质量/GPU 在下方；缺失目录提示紧贴目录控件。
  2. `2 · 导出队列` card：标题旁显示任务数；动作区按「全部添加 / 启动队列 / 清除已完成」排序，启动保持唯一主按钮。
- 任务行增加左侧状态标记或图标槽；任务名、状态、进度、冻结参数、文件动作按固定顺序排列。
- 不改队列控制、FFmpeg、质量映射、路径分配和 store 镜像逻辑。

### E. 通知

- 顶部胶囊改为右上角 notification cards，宽度 340–380px。
- 卡片包含状态图标、固定标题（处理中 / 已完成 / 操作失败）、正文和独立关闭按钮。
- success / error / info 只改变图标、细边框、进度/弱光晕；卡片本体保持同一近黑底。
- 保留自动消失；支持减少动态效果；不把整张卡片做成关闭按钮。

## 不做

- 不复制三个网站的代码，不新增 Aceternity / Animate UI / Origin UI 依赖。
- 不新增远程字体、CDN、运行时联网依赖。
- 不改导出任务 store 数据结构、导出流程、FFmpeg、Render Plan、路径策略、压缩算法或 Rust 媒体逻辑。
- 不做循环装饰动画，不恢复 ClickSpark / SpecularButton。

## 验收

1. `npm run verify:core`
2. `npm test`
3. `npm run build`
4. 构建独立 Tauri QA `.app`，检查首页、导出中心、批量导出、视频导出空态/进行中/完成态。
5. 实际导出短视频并解码验证输出。
6. `tauri build --bundles dmg`，挂载检查 `.app`、签名和资源。
7. 新 DMG 验证成功后，删除 `release/` 中旧 DMG，仅保留新包与校验值。
