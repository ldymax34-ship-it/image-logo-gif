# 压缩工具交互修复（2026-10-19）

## 用户真实任务链

导入图片或视频 → 选择输出倾向 → 查看预计结果 → 放大检查细节 → 保存 → 返回工具箱。

## 当前主要问题

用户手动验收发现：图片与 GIF 不能放大细节；图片页返回按钮无效；保存反馈改变底栏布局；视频播放与时间轴不同步；预设宽度要求用户理解像素数；侧栏展开按钮偏离图标中线且右侧留白较大。

## 建议删除

三个 GIF 预设倾向中的宽度输入。折叠侧栏不保留单侧滚动条预留空间，展开按钮不继承自动左边距。

## 建议保留

单图对比、单视频截取、手动计算预览、四种输出倾向、8,000,000 字节上限、两次完整编码限制、取消与非覆盖导出。自定义倾向仍显示输出宽度与最低宽度。

## 交给成熟库的部分

编解码沿用 @jsquash 与 FFmpeg；视频同步使用平台 `timeupdate` / `currentTime`，放大使用 CSS 尺寸与原生滚动区域，不新增画布编辑器或依赖。鼠标平移仅设置原生 scrollLeft/scrollTop，不移动 DOM 或生成新图；图片分割拖动限定在分割线，浏览器原生拖图被禁止。

官方参考：
- https://developer.mozilla.org/en-US/docs/Web/API/HTMLMediaElement/timeupdate_event
- https://developer.mozilla.org/en-US/docs/Web/API/HTMLMediaElement/currentTime

## 最小修改方案

- `PreviewViewport.vue` 用于图片双图、GIF 参考帧与最终 GIF：适应、1:1、缩放至 400%、鼠标抓手拖动平移与原生滚动查看细节。缩放只改变查看状态，不改变编码尺寸、字节或格式。图片两侧共用同一内容区域与查看位置。
- 图片页直接调用既有返回回调，GIF 继续保留原来的退出确认。
- 图片底栏固定高度，保存信息与按钮保留固定区域，避免保存提示出现时挤动主预览。
- 时间轴点击、拖动、键盘输入定位原片；原片播放与播放器定位更新播放头，正常播放不启动分析或编码。
- GIF 预设不发送指定宽度，复用现有短样本预算计算。参考帧尺寸与正式生成首次自动尺寸都使用相同输入、倾向系数、宽度下限和预算。自定义仍以用户尺寸为第一轮输入，超限才缩宽。
- 侧栏只修折叠状态下的展开按钮布局与滚动条预留，不调整工具顺序或其他页面功能。GIF 左栏长说明允许换行，窄窗口双预览上下排列，避免挤压文字。

## 明确不做

不做批量图片、视频剪辑、多轨、自由画布、全局 UI 重设计、编码器开发或新依赖。不修改 Windows sidecar、更新、签名或发布链路。

## 包体影响

无新增依赖、运行时、WASM 或二进制资源；新增 Vue 查看组件与少量交互代码。实际构建及安装包大小记录在本轮 CHANGELOG，不能用前端增量代替 Windows 安装包实测。

## 验收场景

自动测试覆盖查看倍率、适应复位、图片返回与 GIF 退出确认、播放头双向同步且不启动分析、预设隐藏尺寸与自定义显示尺寸、真实 FFmpeg 自动尺寸预览和编码。手动验收仍需确认滚动细节、图片对比、保存时不抖动、侧栏几何及视频拖动手感；不以单元测试代替窗口验收。
