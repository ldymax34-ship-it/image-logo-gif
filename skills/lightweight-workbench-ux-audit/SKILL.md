# 轻量工作台交互审查

## 作用

在修改品宣物料工作台的 UI、流程或画布交互前，先做一次只读产品审查。目标是删除重复、缩短任务链、把通用交互交给成熟库，并阻止功能膨胀。

本 Skill 不直接写代码。

## 必须输入

- 用户当前要完成的真实任务
- 当前页面或模块代码
- `AGENTS.md`
- `docs/PRODUCT_BOUNDARIES.md`
- 涉及模块的现有测试和状态模型
- 如新增依赖，当前安装包体积审计

## 审查步骤

### 1. 重写真实任务链

不用现有页面标题或组件名，按用户动作写成 3–7 步。

示例：

```txt
导入底图
选择需要显示的 Logo
拖动和缩放
确认 CPR
导出
```

### 2. 建立对象能力表

对每个对象列出：

- 是否可见
- 是否可选中
- 是否可拖动
- 是否可缩放
- 是否可旋转
- 是否可新增或删除

对象表中没有的能力一律视为范围外。

### 3. 找重复控制

检查是否同时存在多套等价操作，例如：

- 拖动 + 横移滑块 + 数字框
- 画布缩放 + 素材缩放混用
- 多个位置相同的导出按钮
- 相同设置同时出现在模块和全局设置

优先保留：

- 日常操作最直接的一种
- 必要的精调方式
- 明确的主操作

其余建议删除，不做“为了兼容习惯全部保留”。

### 4. 判断交互归属

- 位置、大小：画布直接操作
- 精确数值：当前对象属性区
- 显示、语种、格式：参数面板
- 导入、导出：主操作
- 命中、拖动、缩放：成熟交互库
- 业务规则、命名、导出：现有工作台

### 5. 检查产品越界

逐项确认是否引入：

- 通用编辑器能力
- 新的状态模型
- 新模块或设置页
- 大型运行环境
- 模型权重
- 完整字体家族
- 超过 10MB 的发行包增量
- 与当前任务无关的重构

发现任一项时，默认阻止，除非用户明确批准。

### 6. 给出最小方案

优先顺序：

1. 删除
2. 合并
3. 复用现有状态或组件
4. 接成熟开源能力
5. 最后才是新增代码

不得以“未来扩展”为理由增加复杂度。

## 固定输出

```md
# 交互审查结论

## 用户真实任务链

## 当前主要问题

## 建议删除

## 建议保留

## 交给成熟库的部分

## 最小修改方案

## 明确不做

## 包体影响

## 验收场景
```

## 完成前检查

- 是否只围绕用户当前确认的任务
- 是否优先减少而不是增加
- 是否避免重写成熟交互
- 是否保留现有正式导出链路
- 是否明确包体变化
- 是否列出不做项
- 是否在审查阶段没有修改代码
